# case-a Q1–Q5 사전 계획

범위: General worker의 코드 품질 Q1–Q5만 검토한다. 전체 ReviewLens 또는 독립 audit는 수행하지 않는다. 비교 기준은 base `42a7eb3067215787e75bdbf07e110d3f0f136cfd`, target `c70a8fca8b9c66e61e7210f298fdbeacc039cf99`이다. REQUEST.md를 요구사항 근거로 읽고 변경 파일, baseline, 실제 호출자와 테스트를 추적한다. 다른 case, refs.json, ground-truth.md, 다른 worker 산출물, 평가 자료와 범위 밖 git history는 읽지 않는다.

| 항목 | 계획한 독립 확인 범위와 근거 |
| --- | --- |
| Q1 | 변경 책임의 이름, 분기, 실행 경로를 baseline과 비교하고 진입 호출자에서 결과까지 추적하여 현재 이해 비용과 최소 명료화 가능성을 확인한다. |
| Q2 | 변경 함수의 입력 공급자, 반환값 소비자, 부수효과를 추적하여 책임과 interface가 내부 순서를 노출하는지 확인한다. |
| Q3 | 새로 변경된 상태의 생산·갱신·소비 지점을 찾아 소유권, 위치 기반 필드, 중복 상태 invariant를 baseline 및 기존 타입/검증과 비교한다. |
| Q4 | 추가 추상화와 dependency, 확장 지점을 실제 호출자의 필요 및 테스트 seam과 대조하여 현재 불필요한 간접화인지 확인한다. |
| Q5 | 현존 정책의 변경 지점과 관련 테스트를 저장소 내에서 검색하여 정책 분산과 테스트 setup 비용을 확인한다. 변경 코드와 기존 구현의 공유 가능성은 실제 계약 차이를 함께 확인한다. |

실행: 허용된 로컬 `python3 -m unittest -v`를 실행하고 결과를 기록한다. 소스 수정, dependency 설치, network, agent 위임은 하지 않는다. 각 Q 항목의 상태와 근거, 반증, 실제 검사 범위와 실행 상태를 남긴다. 유지보수 advisory와 결함 후보를 분리하며 제안 개수를 채우지 않는다.
